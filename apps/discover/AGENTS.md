# Discover

The public discovery site (`tattoodrip.app`, D05 onward): TanStack Start + Router + Query, React 19, Tailwind v4 and shadcn/ui. File routes: `src/routes`; UI primitives: `src/components/ui`; site shell: `src/components/layout`; discovery primitives: `src/components/discovery`; homepage sections: `src/components/home`; directories and style/location pages: `src/components/directory`; profiles (D08): `src/components/profile`; the gallery, artwork pages and every photo tile (D09): `src/components/gallery`; settings, context, routes, SEO: `src/lib`. Imports: `#/` maps to `src/`.

Boundaries are in the [root instructions](../../AGENTS.md): no database, no auth, no platform imports. Every read goes through `createDiscoverClient` (`@tattoo-drip/sdk`) and `discoverQueries` (`@tattoo-drip/react`) from the router context (`context.discover.client`, `context.queryClient`), one of each per request. Read [frontend guidance](../../docs/discover/frontend.md) before changing routes, data loading, settings, SEO or design tokens.

- Links use `paths` from `src/lib/routes.ts`; studio and artist links go through `profileDestination` (`src/lib/destinations.ts`: Discover's profiles since D08), photo tiles through `ArtworkTile` (`tattooDestination`: the artwork page, D09); booking links only through `bookingLinks` (`src/lib/booking.ts`), from the API's `bookingUrl`/`storefrontUrl`, never built from input. Never use the legacy Studio OS paths (`/login`, `/signup`, `/dashboard`, `/t/…`, `/sw.js`…): nginx sends them to Studio OS (`docs/discover/domain-migration.md`, "Legacy URLs"). Sign in and Get started link to Studio OS's own origin (`APP_URL`).
- Indexing stays off unless `DISCOVER_INDEXING=on`; robots are decided once in the root route (`pageState`): an unfinished page sets `staticData: { noindex: true }`, an empty one returns `noindex: true` from its loader, never its own robots tag; JSON-LD only through `structuredData` (D10, frontend guidance, "SEO and indexing"). No fabricated listings, numbers or reviews; a page not built yet says so (`FoundationNotice`).
- Colours, type and spacing come from the tokens in `src/styles.css`; no hex values in components.
- Country (D06.5): loaders read the page's country from `context.country` and pass it to every country-aware query (it is then in the key); location pages (D07) pass their own country instead. Never read `CF-IPCountry`, redirect or hide a profile by country; pages stay `private, no-store` (frontend guidance, "Country").

Run from `apps/discover`: `pnpm dev` (port 3100, loads `.env.local`, see `.env.example`), `pnpm test` (`node:test` + `tsx`, `test/`; the server test needs a build), `pnpm typecheck`, `pnpm build` (ends with the browser-bundle secret check), `pnpm generate-routes`. `src/routeTree.gen.ts` is generated. Browser-check UI changes.
