# Database conventions

PostgreSQL 18. Every migration follows these rules; the reasoning is in `docs/data-model.md` (Tenant ownership).

- **Primary keys are UUIDv7, generated by Postgres.** They are time-ordered, so inserts stay index-friendly, and they are safe to expose in URLs and the API. `uuidv7()` is built into Postgres 18. The first migration (`ensure_uuidv7`) does nothing there. On older Postgres it enables the `pg_uuidv7` extension and adds a `uuidv7()` wrapper, or fails with a clear error if the extension isn't available.

  ```ts
  table.uuid("id").primary().defaultTo(this.raw("uuidv7()"));
  ```

- **Instants are `timestamptz`, stored in UTC.** Pass `{ useTz: true }` explicitly. App code works with Luxon `DateTime` in UTC and converts to the studio's time zone only for display.

  ```ts
  table.timestamp("created_at", { useTz: true }).notNullable();
  ```

- **Every tenant-owned table has `tenant_id`.** That is every table except `users` and platform reference lists. The column is `uuid not null`, references `tenants`, and is indexed. References between tenant-owned rows include `tenant_id` in a composite foreign key, so the database rejects cross-tenant links. Row-level security on these tables is planned (`docs/architecture.md`, Tenant context).
- **Foreign keys are `uuid` columns with an index.**
- **Phone numbers are E.164,** defaulting to +977. **Money is an integer in minor units** (paisa) with a currency, `NPR` by default.
- **Business records are soft-deleted.** Tenant-owned tables (and `tenants` itself) get a nullable `deleted_at timestamptz`, and their models use the `withSoftDeletes` mixin (`#models/mixins/soft_deletes`). Unique rules that a deleted row must not block become partial indexes, `... WHERE deleted_at IS NULL` (for example, a removed member can be invited back). Keep a plain unique index when a deleted row should keep its value forever: tenant slugs stay reserved so a deleted studio's subdomain is never reused. Not soft-deleted: `users` (account and personal-data deletion must really erase), payments (never deleted at all), and queue tables.

  ```ts
  table.timestamp("deleted_at", { useTz: true }).nullable();
  ```

`database/schema.ts` is generated by `node ace migration:run`; never edit it by hand. Never edit a migration that has run anywhere; add a new one instead.
