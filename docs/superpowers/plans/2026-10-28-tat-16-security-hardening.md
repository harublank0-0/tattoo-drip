## 4. Decisions

- **D1 (isolation-1, ruled): artists get `client.name: null`, owners unchanged.** The lookup keeps `state: "found"` and the id, so the form still posts `clientId` and the "Returning client" badge stays. The refusal for a number taken meanwhile drops the name for artists and skips the `findByPhone` query for them. Rejected: lookup for owners only (the ruling keeps booking for artists).
- **D2: the success flash after an artist books an existing client keeps the name.** The booking makes the project theirs, and the requirements give an artist their assigned projects' client. Rejected: hiding it there too (the next page shows the name anyway).
- **D3 (exposure-2): the email fallback becomes an explicit owner-only choice in `memberNames(userIds, { emails })`.** Owners keep `fullName ?? email` (they see emails on Members). For an artist the controller passes `emails: false`, the map holds `null` for a member without a full name, and `paymentsCard` words it "an owner" (only owners decide or record payments, `PaymentService.assertOwner`); an id with no user stays "a deleted account". The email never leaves the service for an artist's request. Rejected: rewriting in `paymentsCard` only (the email would still be loaded and one refactor away from the page).
- **D4 (abuse-4): the rule is an allow-list on code points.** The email shows the first word only when it is made of letters (`\p{L}`), combining marks (`\p{M}`: Devanagari vowel signs, virama, nukta), ZWNJ/ZWJ (U+200C, U+200D), hyphen and apostrophes (`'`, `’`), with at least one letter; anything else ("https://…", "evil.com", "a@b.co", "J.R.", digits, an emoji, a full-width dot) reads "A client". Without a dot, colon or `@`, no mail client auto-links a word. A new pure `emailName(clientName)` in `alerts.ts` is used by `inquiryIntro` and `proofIntro` only; `firstName` stays as it is for chat messages and dashboard alerts (React text, never linked). Probed with Node: `सीता`, `श्री`, `क्षितिज`, `ज़रीना`, `Ma'ya`, `Anne-Marie`, `O’Brien`, `Zoë`, `Nguyễn`, `محمد` pass; the link shapes above fall back. Rejected: a deny-list of `://`/`www.` (misses `evil.com`), refusing such names at intake (a validation change for a display problem, and old clients keep their names).
- **D5 (web-2): `Cache-Control: private, no-store` is set in `InertiaMiddleware.share()` when `ctx.auth?.user` is set, with `safeHeader`.** That is the one place that runs exactly on every page render, both kinds (fact list). `handle` cannot do it (server middleware, see facts). Rejected: `AuthMiddleware` (misses the 404 and error pages rendered for a signed-in user, and the verify-email and invitation pages outside the `auth` group), and a header for every Inertia page including guest ones (the ruling is authenticated pages; guest pages already set their own where they hold a token).
- **D6 (exposure-1, ruled; the design task): an artist's deposit must be at least the studio's default and never zero.** `artistDepositFloor(total, percent)` (paisa, bigint) = the default percentage of the total in whole rupees, rounded half up and never above the total's whole rupees, exactly as the quote form already fills it in, and never under NPR 1. A studio without a default (null) or with 0% gives a floor of NPR 1, so "zero needs an owner" always holds (U2). Why the prefill's rounding: the amount the form suggests must always pass. Owners have no floor.
- **D7: the rule lives in `ProjectService`, the authority for every caller.** `issueQuote` checks before its transaction (pure: nothing is stored, nothing is locked); `acceptQuote` checks the stored current quote under the project lock, after the existing `not_quoted`, `quote_changed` and `expired` checks. Both throw a new `DepositFloorError(floor, percent)`. `QuotesController.store` turns it into a field error on `depositAmount` (so the first-quote form and the Revise sheet keep what was typed, `sheetStep` keeps the sheet open under the field), `accept` into the error flash. Rejected: a new `QuoteRuleError` reason (it carries no amount for the message, and `RULE_MESSAGES` would need it for every route).
- **D8: "accepting follows the same rule" means: an artist may mark accepted only a current quote that meets the floor.** A quote an owner issued with a lower or zero deposit is confirmed by an owner. The floor uses the studio's percentage at accept time. Existing quotes are not touched: no migration, no backfill, no re-check of booked projects; an old artist-issued zero-deposit quote still awaiting "Client accepted" now needs an owner to confirm it.
- **D9: `setPrice` is unchanged.** It prices a project already booked through a direct booking (requirements.md:45, "no deposit step"); its zero deposit decides nothing. Artists keep it, as `ARTIST_ROUTES` pins.
- **D10: the page shows the floor, the server enforces it.** The server sends two booleans for artists, `form.depositFloor` (the Deposit field explains the minimum) and `ownerAccepts` (the current quote's deposit is under the floor, so "Client accepted" is not offered and the Quote card says why). The minimum depends on the typed price, so the dashboard computes it with its own `artistDepositFloor` next to `suggestedDeposit`; a unit test keeps it equal to the server's on a table of cases. No `min` attribute on the input (the browser's own bubble is not our wording; the server's field error is). Booleans keep the TAT-108 money comparator green.
- **D11: storefront cleanup removes exactly the packages proven unused** (facts), including the two prototype fonts and the two store packages and `@tanstack/devtools-event-client`, which the review did not list but `rg` proves unused. Every remaining `latest` becomes `^<resolved version>`. `nitro` stays. The devtools stay in `dependencies` (moving them is not asked and changes nothing in the built output).
- **D12: nodemailer through a scoped override** `'@adonisjs/mail>nodemailer': ^10.1.4` in `pnpm-workspace.yaml`, with a comment like the `@boringnode/queue` one. It is outside `@adonisjs/mail`'s declared `^9.0.3`, but nodemailer 10's only break is Node ≥ 20 and we run 24.3.0. If the mail specs, the typecheck or the smoke in Task 8 fail, the builder reverts the override and reports; the smallest alternative is then to keep 9.1.1 and note that every address the app sends to is either a validated staff address or a canonical, validated account email (`validators/user.ts:8`, `canonicalEmail`), so the parser never sees free text, and to watch for an `@adonisjs/mail` release on nodemailer 10.
- **D13: the CI audit gate is a follow-up**, because `pnpm audit --prod --audit-level high` is expected to stay red on transitive build tools (facts). Task 8 records the before/after numbers; the report proposes the follow-up ticket text.
- **D14: the storefront part of TAT-53's "prototype leftovers" is done here** (`development.md:86` names TAT-53 for removing them). The builder says so in the report; the coordinator updates Linear.
