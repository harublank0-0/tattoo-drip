## 4. Decisions

Made by the planner (do not reopen):

1. **Storage: columns of `tenants`, not a table** (like the cover, TAT-116). `storefront_theme`, `storefront_sections`, `brand_accent`, `brand_accent_dark`, `brand_font`, `logo_image_key`, `logo_image_width`, `logo_image_height`. The public read and the settings page cost no query (the row is already loaded), there is no new RLS table, and the configuration's size is capped by construction (the TAT-54 carry-forward "cap the stored size" and "strip it before dehydration" are moot: the served object is about 300 bytes). Rejected: a `storefront_configurations` table (a query per read, an RLS table, for one row per tenant); one `jsonb` column (Lucid types it `any` and the database could not check its parts).
2. **Database checks guard the shape; the app guards the lists.** CHECKs: `#rrggbb` lowercase for both accents, a slug-shaped theme and font, sections as a comma list of up to 8 lowercase words that includes `inquiry`, the logo's three columns all or none. Which theme, font and section keys exist is the app's list (`#modules/storefront/look`), so TAT-120 adds a theme without a migration. Sections are stored as `varchar` `artists,inquiry` (the visible sections in order) because Lucid's schema generator maps no array type (`node_modules/@adonisjs/lucid/build/src/orm/schema_generator/mappings.js`; `database/schema_rules.ts` is empty), so `database/schema.ts` would type the column loosely; rejected: `text[]`.
3. **One rules module, pinned to the storefront by reading its files.** `app/modules/storefront/look.ts` copies the lists, the two papers, the two theme violets and the 4.5:1 minimum, with the WCAG maths. `tests/unit/modules/storefront/look.spec.ts` reads `apps/storefront/src/studio/theme/{config.ts,branding.ts,color.ts}` and `src/styles.css` as text and fails when a value drifts (reading a file is not an import; `apps/*` still never import each other). Rejected: a shared package (packages may not hold app rules and it would add a build step).
4. **Validate on write, filter on read.** The validator refuses an unknown theme, font or placement, a colour that is not `#rrggbb` (any letter case; stored lowercase), an accent under 4.5:1 on `#f7f3ee` and a dark-mode colour under 4.5:1 on `#14110f`. On read, `lookOf(tenant)` keeps each stored value only while it is on today's list and readable, else that value's default alone, so the API always matches the contract's enums. The storefront's own checks stay as they are.
5. **One check covers text and buttons.** `--on-stencil` is the paper, so paper text on an accent button has exactly the accent's ratio on the paper: refusing under 4.5:1 protects links, the button label and the focus ring at once. No second rule. Red near `--destructive`: a fixed sentence in the field's description, not a refusal.
6. **The contract** (`openapi.yaml`): `Studio.storefront` (required, like every `Studio` property) is a narrowed `StorefrontConfiguration`: `theme` enum `[stencil-and-ink]`; `branding` `{ logo: Image | null (alt always null), colors: { accent, accentDark: string | null, pattern ^#[0-9a-f]{6}$ }, font: enum [eczar, serif, sans] }`, `additionalProperties: false` throughout; `sections` 1 to 2 items `{ type: enum [artists, inquiry] }`. `branding.heroImage` and the section `props` leave the schema (the hero is `Studio.cover`; `readSections` never read `props`). Every enum's description says "treat an unknown value as the default" because the lists will grow.
7. **Sections in the dashboard are one three-way choice** (the storefront supports exactly two sections, `inquiry` always shown): "Artists, then the form" (`artists,inquiry`), "The form, then artists" (`inquiry,artists`), "Don't show the artists list" (`inquiry`). The "How booking works" strip and panel are fixed parts of the hero and the inquiry section, not sections. Rejected: toggles plus up/down buttons for two rows.
8. **The theme picker is a radio group even with one theme**, built from the server's list, so TAT-120 adds entries and nothing else. Rejected: hiding it (the ticket says owners pick it, and TAT-120 would have to add it).
9. **Logo: a new public purpose `studio_logo` with `VARIANT_WIDTHS`**, set, replaced and removed exactly like the cover. `setCover`/`removeCover` and `setLogo`/`removeLogo` share one private pair in `TenancyService` (a slot table names the purpose and the three columns); the public signatures of the cover methods do not change and their 20 tests are the regression net. Rejected: copying the 50 lines.
10. **The cover stays in Settings, Studio profile** (TAT-116); Page look shows whether there is one and links to `…/settings/profile#cover-photo`. One upload, one place.
11. **Names:** the page is "Page look" (route `tenant.settings.look`, path `/settings/look`, icon `Palette`), second in the settings nav; the logo routes are `tenant.settings.logo.update` / `.destroy` (`PUT`/`DELETE /settings/logo`). "Page look" is plain words for an owner; "branding" and "storefront" are ours.
12. **Colour fields:** a text box (`#0f766e`, empty means the theme's violet) with a native `<input type="color">` swatch beside it (no `name`: only the text box is sent) and a Clear button; the swatch starts at the theme's violet while the box is empty. The dark-mode colour is a second, optional field. A native colour input adds no dependency and works on Android Chrome and iOS Safari.

```ts
/**
 * A studio's page look (TAT-56): what an owner may pick for the studio page,
 * as the storefront's theme reads it (apps/storefront/src/studio/theme/).
 * Pure. Apps may not import each other, so these are copies;
 * tests/unit/modules/storefront/look.spec.ts reads the storefront's files and
 * fails when one drifts. Never markup or CSS: keys from fixed lists and
 * checked "#rrggbb" colours.
 */

export const THEME_KEYS = ["stencil-and-ink"] as const;
export type ThemeKey = (typeof THEME_KEYS)[number];
export const DEFAULT_THEME: ThemeKey = "stencil-and-ink";

export const FONT_KEYS = ["eczar", "serif", "sans"] as const;
export type FontKey = (typeof FONT_KEYS)[number];
export const DEFAULT_FONT: FontKey = "eczar";

export const SECTION_KEYS = ["artists", "inquiry"] as const;
export type SectionKey = (typeof SECTION_KEYS)[number];

/** Where the artists list goes; the inquiry section is always shown. */
export const ARTIST_PLACEMENTS = {
	first: ["artists", "inquiry"],
	last: ["inquiry", "artists"],
	hidden: ["inquiry"],
} as const satisfies Record<string, readonly SectionKey[]>;
export type ArtistPlacement = keyof typeof ARTIST_PLACEMENTS;
export const ARTIST_PLACEMENT_KEYS = Object.keys(
	ARTIST_PLACEMENTS,
) as ArtistPlacement[];
export const DEFAULT_SECTIONS = ARTIST_PLACEMENTS.first;

/** The storefront's papers (branding.ts LIGHT and DARK) and its minimum (color.ts). */
export const LIGHT_PAPER = "#f7f3ee";
export const DARK_PAPER = "#14110f";
export const MIN_TEXT_CONTRAST = 4.5;
/** The theme's own violets (styles.css --stencil, light and dark): where an empty colour picker starts. */
export const THEME_ACCENT = "#43389a";
export const THEME_ACCENT_DARK = "#a99cff";

export const HEX_COLOR = /^#[0-9a-f]{6}$/;

function luminance(color: string): number {
	const [r, g, b] = [1, 3, 5].map((start) => {
		const c = Number.parseInt(color.slice(start, start + 2), 16) / 255;
		return c <= 0.04045 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4;
	});
	return 0.2126 * r + 0.7152 * g + 0.0722 * b;
}

/** WCAG 2.x contrast of two lowercase "#rrggbb" colours, as the storefront computes it. */
export function contrastRatio(a: string, b: string): number {
	const la = luminance(a);
	const lb = luminance(b);
	return (Math.max(la, lb) + 0.05) / (Math.min(la, lb) + 0.05);
}

/** Whether text in `color` reads on `paper` (4.5:1 or more): what the storefront needs to use it. */
export function readsOn(color: string, paper: string): boolean {
	return HEX_COLOR.test(color) && contrastRatio(color, paper) >= MIN_TEXT_CONTRAST;
}

export type PageLook = {
	theme: ThemeKey;
	/** The light scheme's accent, or null for the theme's violet. */
	accent: string | null;
	/** The dark scheme's accent, or null: the storefront lightens `accent`. */
	accentDark: string | null;
	font: FontKey;
	/** The sections shown, in order; always holds "inquiry". */
	sections: SectionKey[];
};

function isOneOf<T extends string>(list: readonly T[], value: unknown): value is T {
	return typeof value === "string" && (list as readonly string[]).includes(value);
}

/** A stored section list: known keys, each once, then "inquiry" if it was left out (the storefront's readSections). */
export function sectionsOf(stored: string): SectionKey[] {
	const sections: SectionKey[] = [];
	for (const key of stored.split(",")) {
		if (isOneOf(SECTION_KEYS, key) && !sections.includes(key)) sections.push(key);
	}
	if (!sections.includes("inquiry")) sections.push("inquiry");
	return sections;
}

export function placementOf(sections: readonly SectionKey[]): ArtistPlacement {
	const artists = sections.indexOf("artists");
	if (artists === -1) return "hidden";
	return artists < sections.indexOf("inquiry") ? "first" : "last";
}

export type StoredLook = {
	storefrontTheme: string;
	storefrontSections: string;
	brandAccent: string | null;
	brandAccentDark: string | null;
	brandFont: string;
};

/**
 * The look the API serves and the settings page shows: each stored value
 * while it is on today's list (and a colour while it reads on its paper),
 * else that value's default alone. The database checks only the shapes.
 */
export function lookOf(row: StoredLook): PageLook {
	return {
		theme: isOneOf(THEME_KEYS, row.storefrontTheme) ? row.storefrontTheme : DEFAULT_THEME,
		accent: row.brandAccent !== null && readsOn(row.brandAccent, LIGHT_PAPER) ? row.brandAccent : null,
		accentDark:
			row.brandAccentDark !== null && readsOn(row.brandAccentDark, DARK_PAPER)
				? row.brandAccentDark
				: null,
		font: isOneOf(FONT_KEYS, row.brandFont) ? row.brandFont : DEFAULT_FONT,
		sections: sectionsOf(row.storefrontSections),
	};
}
```

## 11. Review focus

- **Role scoping and isolation:** the four routes are `OWNERS`; `PageLookController` and `StudioLogoController` read the tenant only from `tenantContext(ctx)`; `updateLook` / `setLogo` / `removeLogo` from B's context find nothing; the isolation cases' positive controls really change A's row (DELETE needs the seeded logo).
- **Information exposure:** the public `Studio` has exactly the documented `storefront` fields; no `logoImageKey`, `logo_image`, timestamps or dashboard-only props; the settings page object holds no key either.
- **Never HTML or CSS:** every stored value is a key from a list or a lowercase `#rrggbb`, checked by the validator, by the database's shape checks, by `lookOf` on read and by the storefront's `parseThemeConfig` and `isSafeCss`; no string from the owner reaches a `<style>` except a checked hex.
- **The shared cover code:** the refactor keeps the cover's order of operations (store, `afterRollback` with no await between, lock, swap, `afterCommit` delete; `deleteOrThrow` under the lock) and all 20 cover tests pass unchanged.
- **Contrast:** the platform's maths equals the storefront's (the pinned numbers); the papers and the minimum are pinned by reading the storefront's files.
- **Query counts:** no new query on `getStudio`, none on the settings page.
- **Accessibility:** radio groups in `FieldSet` with legends; the swatch's `aria-label`; field errors tied to their inputs; 44 px targets; the font samples' Devanagari line height; the logo preview's alt.

## 12. Risks and rollback

- **The default look changes by accident** (a fixture with the default `storefront` renders differently): the snapshot test catches it; the default configuration writes no `<style>`.
- **Origin mismatch hides logos in development:** the storefront accepts images only from `API_URL`'s origin; if `APP_URL` differs (`localhost` vs `127.0.0.1`), logos, covers and work photos all vanish. Set both to the same origin in the lane.
- **Cache delay looks like a failed save:** the note and the toast say 15 minutes; without a CDN (today) the next page load shows it.
- **A white see-through logo vanishes on the light plate:** the dashboard preview shows the same tile, and the logo's description says a dark logo works best (U3).
- **Refactoring the cover:** if a cover test fails, revert to two copies rather than weakening a test.
- **Contract enums grow (TAT-120):** the enums' descriptions say to treat unknown values as defaults, and the storefront already does.
- **Rollback:** revert the branch's commits; the migration's `down()` drops the constraints and the eight columns (logo files stay on disk under `tenants/<id>/studio_logo/`, like any soft-deleted record's files); the storefront falls back to the default theme when `storefront` is absent.
