# Studio page: profile, artists, Instagram link, intake mount point (TAT-48)

Date: 2026-10-18
Refs: TAT-48. Builds on TAT-12 (`tenantMiddleware`, `requestStudio()`, `storefrontConfig()`, `tenantOrigin()`, the static 404/503/landing pages, the `node:test` + `tsx` runner), TAT-23 (router context `{ queryClient, tattoo }`, `loadStudio`, `rethrowAsNotFound`, `query({ …, staleTime: "static" })`, query defaults), TAT-44 (`Studio`, `Artist`, `listArtists`, the `ArtistSlug` pattern). Blocks TAT-57 (intake form), TAT-78, TAT-54, TAT-79, TAT-53. Linear has no comments on TAT-48 (checked 2026-10-18). Written without the user (unattended run): every open question is a ruling below.

## Goal

The first customer-facing page: a client opens `blackneedle.tattoodrip.com` from an Instagram bio on a phone, sees who the studio is, how to reach it and who its artists are, and can send an inquiry (by WhatsApp or email until TAT-57's form). Every artist has a shareable link that asks for them by name. The prototype's mock data and pages go. Storefront only: no platform, contract or SDK change, no dependency change, **no new environment variable**.

## Base

Designed on 601fb7b (TAT-44's design commit, on the designs of TAT-12/23). The build needs the built TAT-12 (reviewed tip 4a60fc9 or later), TAT-23 and TAT-44: rebase onto their built tips first. The plan's Task 0 checks the names it uses and stops otherwise.

## Rulings

1. **Two routes.** `/` is the studio page; `/artists/$slug` is one visible artist: the per-artist intake link an artist shares (TAT-78 grows it into a full artist page in V1). Every other path, including the prototype's `/flash`, `/portfolio`, `/aftercare`, `/about`, `/booking`, `/admin/*`, is the router's not-found page. Rejected: `/?artist=<slug>` (TanStack parses search values as JSON, so `?artist=47` arrives as a number and `?artist=1e3` as 1000; an uglier link to share; a second contract on one page).
2. **Data: the studio from the cache, the artists list once, no `getArtist`.** Loaders use TAT-23's `queryClient.query({ ...tattooQueries.x(client), staleTime: "static" })`: the studio (TAT-12's lookup already seeded it) and `tattooQueries.artists`. The artist page finds its artist in that list by exact slug, after checking the `ArtistSlug` shape (a malformed slug is a not-found without any API call). Hidden, deleted, renamed and unknown artists are not in the list, so they are the same not-found as `getArtist`'s 404. Why: one cache entry for both pages, one API read per page, and the intake form's artist choice needs the list anyway. The list's own 404 (the studio went away) is a not-found; any other failure is the error page. Rejected: `getArtist` (a second read per page; seeding it from the list doubles the dehydrated payload).
3. **Loaders return view models; components take props.** Pure functions (`studioViewModel`, `artistViewModels`, `inquiryState`, `inquiryChannels`, the SEO builders) turn API data into what the page shows; loaders return it, components render it with no router or query hooks. Why: render tests with `react-dom/server` and no router; no query observers, so a CDN-cached page older than 60 s never refetches in the browser. Rejected: `useSuspenseQuery` in components (refetch on mount of aged HTML, from every visitor).
4. **Plain anchors, no `<Link>`.** Two small, CDN-cached pages; links work before hydration on slow connections; components stay router-free. Rejected: `<Link>` with intent preloading (a router in every render test for a negligible gain).
5. **Render only the allow-list, as text.** No `dangerouslySetInnerHTML`, no `style` props (CSP-friendly). User text is cleaned (`\r\n` to `\n`, control characters, bidi embeddings, overrides and isolates and the byte order mark dropped, the joiners U+200C and U+200D kept for Devanagari and emoji, at most one blank line) and shown with `white-space: pre-line`. An `href` is only the page's own path or fragment, `https:`, `tel:+`, `mailto:` or `viber://chat?`: API URLs are parsed again (social links https only, photos http(s)), phones must be E.164, emails a conservative shape, else no link. Chat links copy the platform's `chatLinks()` exactly (`https://wa.me/<digits>`, `viber://chat?number=%2B<digits>`), in a storefront-local builder (the storefront can't import the platform). Web links get `rel="noopener noreferrer"`; nothing opens a new window (no `target`). JSON-LD is serialized by us with `< > & U+2028 U+2029` escaped, because the router inserts head script children unescaped.
6. **The `#inquiry` section is TAT-57's mount point.** `InquiryState` is `open` (`studioName`, `preferredArtist: { id, name } | null`, `artists`: the accepting ones, by name), `studio-closed`, or `artist-closed` (`artistName`, `studioOpen`). The studio page goes by `studio.acceptingInquiries`; the artist page by that artist's own `acceptingInquiries` (what intake checks for an inquiry naming them). Until TAT-57, `open` shows a fallback: "Message on WhatsApp" with a prefilled message naming the studio (and the artist), "Send an email" with a prefilled subject and body, else "Message on Instagram", else "<Studio> hasn't added contact details yet." TAT-57 replaces only the fallback (`InquiryFallback`), sending `preferredArtist.id` as `preferredArtistId` and offering only `state.artists`. Closed: "<Studio> isn't taking new inquiries right now."; a closed artist's page says so and, when the studio is open, links to `/#inquiry` ("Send <Studio> a general inquiry"); the artist's own closed message shows in their profile (the dashboard's promise: "Shown instead of the request form").
7. **The canonical origin travels like the API connection.** A set-once `SiteRef` joins the router context (`{ queryClient, tattoo, site }`): on the server `tenantOrigin(storefrontConfig(), requestStudio().slug)`, in the browser from the router's dehydrated state (`{ site: { origin } }`, checked to be an http(s) origin). Loaders also run in the browser (a first tap on `#inquiry` does not re-run them, but a repeat navigation to the identical URL does: the router's `sameHref` forces a stale reload; they then read the cache, which `hydrateApi` keeps for the page's lifetime), so they must have it. This amends TAT-23 ruling 5: the browser gets `{ apiUrl, tenant }` and the page's own origin, all public. Rejected: `window.location` (TAT-12: never read the host in the browser; it can differ from the server's canonical); the query cache as a store (garbage-collected after 5 min).
8. **Head per page.** Title: the studio's name; `<artist> at <studio>` (the name alone when they are the same). Description: the intro or bio, one line, at most 160 graphemes (`Intl.Segmenter`, so a Devanagari cluster or an emoji is never split), cut at a space, "…"; else a fixed sentence. `<link rel="canonical">` and `og:url` from the origin; `og:type`, `og:site_name`, `og:title`, `og:description`, `twitter:card`; `og:image` (with width, height, alt) is the artist's photo on the artist page and, on the studio page, the photo of its only artist when it has exactly one. JSON-LD `TattooParlor` on `/` only: name, url, description, telephone, email, address (one line), `sameAs` (social links), image; nothing else. No robots meta on pages (indexable); not-found and error heads are `noindex`. A static `public/robots.txt` allows all (it saves a function run per crawler hit); no sitemap; no generated share image. Staging needs no switch: Vercel previews already send `X-Robots-Tag: noindex`, another staging is TAT-13's.
9. **Caching by match status.** Route `headers`: a page `public, max-age=0, s-maxage=60, stale-while-revalidate=600` (the API's own), a not-found `public, max-age=0, s-maxage=60` (TAT-12's 404), an error `no-store`. Safe because the HTML holds no per-visitor data (no cookies, no key, the same for every visitor of a host). Unmatched paths get no header of ours.
10. **No analytics, no third-party scripts or fonts.** PostHog goes (its provider and its `.env.local.example` lines; its now-unused packages are TAT-53's to remove, rule 14): it shipped in every page's bundle and would see TAT-65b's deposit links. Sentry stays server-only (`instrument.server.mjs`); servers never see URL fragments, so a deposit token in `#…` reaches nothing. The pilot metrics are measured on the platform. The one planned exception is TAT-55's bot challenge, loaded by TAT-57's form.
11. **Visual identity: stencil paper, tattoo ink, transfer violet.** A tattoo starts as a violet stencil transferred to skin; the page borrows that: a cool paper white, a blue-black ink, one violet for everything you can tap. The display face is Eczar 700 (SIL OFL), whose Latin and Devanagari were designed together, so a Nepali studio name keeps the same voice; self-hosted, its three woff2 files and licence vendored in `src/assets/fonts/eczar/` from the `@fontsource/eczar` npm package (no Google Fonts request, no new dependency), `font-display: optional` (a slow first visit keeps the system serif instead of reflowing late), the Latin file preloaded, Latin Extended and Devanagari downloaded only when the text holds them. Body text is the system UI stack (Noto Sans Devanagari, Kohinoor, Nirmala UI cover Nepali). Light by default, dark by `prefers-color-scheme`, no toggle. The one bold element: the studio's name, very large; the one motif: a violet "stencil" frame offset behind each artist photo. Rejected: the prototype's look (two web fonts, near-black with a serif, all-caps eyebrows: the generic default); blackletter or script (a cliché, and unreadable for names); a theme picker (TAT-54).
12. **Text that is Nepali, long or right-to-left.** `dir="auto"` on every user string, `<bdi>` where a name sits inside a UI sentence, `overflow-wrap: anywhere`, headings at line-height 1.12 or more (Devanagari marks), and never letter-spacing, uppercase, line clamps or ellipses on user text. `lang="en"` describes the UI copy only.
13. **Empty and edge states.** No intro, photo, address or links: that part is left out (no placeholders). No visible artist: no Artists section (intake still takes general inquiries). One artist: the heading is "Artist" and there is no per-artist link on `/`. Studio closed: "Not taking new inquiries right now" replaces the call to action. A closed artist shows "Not taking new inquiries" and their message, and no "Ask for" link.
14. **What goes.** Deleted: `src/data/` (mock), the prototype routes listed in rule 1, `src/features/home/*` except the booking form, `src/components/layout/*`, `src/integrations/posthog/`, `public/images/` and `public/prisma.svg`. Kept: `src/components/ui/*` (TAT-57's kit), `src/lib/utils.ts`, `src/env.ts`, the devtools integration. The prototype booking form moves, unmounted, to `src/features/intake/booking-form.tsx` (its schema to `booking-schema.ts`): the development guide names it as the TanStack Form reference and TAT-57 rebuilds it. **No dependency changes:** TAT-12's builder found that `pnpm add`/`remove` in the storefront re-resolves every `latest` specifier in the lockfile, so `package.json` and `pnpm-lock.yaml` stay untouched; the now-unused `posthog-js`, `@posthog/react`, `@fontsource/cormorant-garamond` and `@fontsource/manrope` stay listed for TAT-53, which removes the prototype's leftover packages (with `@tanstack/ai*`). The route tree is regenerated by `pnpm build` (the Start plugin writes the tree and its Register footer); never hand-edited; `generate-routes` only if a build leaves stale entries, then build again (TAT-12's procedure). TAT-53's leftovers (`src/env.ts`'s `SERVER_URL`, the `@tanstack/ai*` packages) stay: nothing here uses them.
15. **Footer: "Studio page by Tattoo Drip", plain text.** Clients should know who runs the page their details go through; no link until a marketing site exists. Rejected: no attribution; a link to the placeholder landing page.
16. **Photos as stored.** TAT-44 serves one image of up to 2048 px (JPEG q85); there are no variants. Roster photos are `loading="lazy"`, `decoding="async"`, `fetchpriority="low"`; the artist page's photo (its largest element) is eager and high priority; `width`/`height` are always set and CSS fixes a 4:5 crop, so nothing shifts. Rejected: an image proxy in the storefront. A small variant (TAT-27/media) must come before a public launch.
17. **Tests: `node:test` + `tsx`** (TAT-12's runner), in `test/studio/` and `test/site/`: the pure modules, the loaders against a fake `fetch`, `renderToStaticMarkup` of both pages with normal, empty, closed and hostile fixtures, and a guard that the prototype is gone. The route glue is covered by typecheck, build and a production run against a fake API.

## UI

**Tokens** (light / dark): paper `#f5f6f8` / `#14121d`; ink `#1b1830` / `#eceaf4` (15.9:1); ink-muted `#5b5870` / `#a7a3bc` (6.3:1, 7.5:1); stencil `#43389a` / `#a99cff` (8.5:1, 7.5:1; links, actions, focus ring, photo frame); stencil-strong `#362c80` / `#c4bbff` (hover); stencil-wash `#e7e4f4` / `#221e38`; line `#d6d4e0` / `#34304a` (hairlines); line-strong `#827e98` / `#6b6684` (chip borders, 3:1). Radius 0.25rem. shadcn's variable names map onto these, so TAT-57's form kit matches.

**Type:** Eczar 700 for h1 (`clamp(2.75rem, 1.5rem + 6.5vw, 5.5rem)`), h2 (`clamp(1.75rem, 1.4rem + 1.5vw, 2.25rem)`), h3 (1.5rem), the artist page h1 (`clamp(2.25rem, 1.5rem + 4vw, 4rem)`) and the artist page's studio bar; body system UI 1.0625rem/1.6, text measure 36rem; status lines 0.9375rem semibold.

**Layout:** container `min(72rem, 100% - 2.5rem)`, left-aligned, one column at 375 px. From 48rem the roster is a grid of `minmax(min(100%, 26rem), 1fr)` rows (photo 9rem left, text right; 7rem beside the name on phones, bio below). From 60rem the profile splits 7:5 (name across, intro left, actions and contact right). Tap targets: actions 3rem, chips and text links 2.75rem. Focus: 2px stencil outline, offset 3px. Motion: only 150 ms colour transitions, off under `prefers-reduced-motion`; smooth anchor scrolling only without it. No entrance animations.

**Copy:** "Send an inquiry" (primary, to `#inquiry`); "Ask for <name>" (per artist, to `/artists/<slug>#inquiry`); "Taking new inquiries" / "Not taking new inquiries"; "Open in Google Maps" (`https://www.google.com/maps/search/?api=1&query=<name, address>`); chips "Instagram", "WhatsApp", "Viber", "Call", "Email", "Facebook", "TikTok", "Website", else the host name, in that order (Instagram first, then ways to reach the studio, then other places); type line "Tattoo studio" / "Independent tattoo artist" / "Tattoo artist at <studio>"; not-found "Page not found" / "This page doesn't exist. The link may be old or mistyped." / "Go to the studio page"; error "This page can't load right now" / "Please try again in a minute." / "Try again" (a link to the same URL).

```text
      ul.links  a.link-chip ×n                a.action-primary #inquiry (if open)
      p street (pre-line) · a maps          section#inquiry  (same component)
  section#artists (if any)                  section  h2 studio name · p type
    h2 Artist(s)                              address.contact · a "See the studio page"
    ul.roster > li > article                footer.site-footer
      figure.artist-photo (lazy)
      h3 name · p status
      p bio · p.note · a "Ask for …" (2+ artists, open)
  section#inquiry  h2 "Send an inquiry" ("Inquiries" while closed)
    InquiryFallback | closed text           (TAT-57 mounts its form here)
footer.site-footer  p studio name · p "Studio page by Tattoo Drip"
```
