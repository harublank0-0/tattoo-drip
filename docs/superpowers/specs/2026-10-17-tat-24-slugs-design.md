# Slugs: validation, reserved names, old-slug aliases (TAT-24)

Date: 2026-10-17
Refs: TAT-24. Builds on TAT-19 (tenants, `tenants_slug_unique`, onboarding), TAT-28/29 (RLS, catalog guard, isolation harness), TAT-26 (studio settings, which kept the slug fixed "until TAT-24") and TAT-31 (artist slugs, which left reserved words to the studio-page route). Blocks TAT-32 (public API, tenant by path), which relies on the rules and the registry below. Linear has no comments on TAT-24, TAT-19 or TAT-32 (checked 2026-10-17), so there are no carry-forwards to honour.

## Goal

A tenant slug is a lowercase DNS label that is unique across the platform and never one of the platform's own names. A studio can change its slug. Its old slugs stay its own for good and keep working (the dashboard redirects them), so a stale link can never reach another studio.

Written without the user (unattended run): every open question is a ruling below. One migration; no API, SDK or OpenAPI change.

## What exists today

- `createTenantValidator.slug`: `trim().toLowerCase().regex(/^[a-z0-9][a-z0-9-]{1,61}[a-z0-9]$/)`. That means 3 to 63 characters with no hyphen at either end. It accepts `a--b`, `xn--80ak6aa92e` (punycode), `12345` and every reserved word. Vine's `toLowerCase` calls `toLocaleLowerCase`, so the Kelvin sign `Kat` lowercases to `kat` and is accepted (checked in Node).
- Uniqueness is only the plain unique index `tenants_slug_unique`, which also covers deleted tenants. `createTenant` turns a violation into `SlugTakenError`. Nothing reads across tenants.
- Nothing can change a slug: the profile form ignores it (a test checks).
- `TenantMiddleware` resolves `:tenant` with `membershipFor(user, slug)` (exact match, live tenant, live membership). Anything else gets the 404 for an unknown URL, and `/t/Black-Needle` is a 404 (a test checks).
- Artist slugs (`ARTIST_SLUG`: 2 to 63 characters, `a--b` allowed) are unique among one tenant's live artists. An independent artist's own profile starts with the tenant's slug.

## Rulings

1. **Shape: a lowercase DNS label, stricter than today.** 3 to 63 characters from `a-z`, `0-9` and `-`, starting and ending with a letter or digit (as today). New: no two hyphens in a row, and at least one letter. Why: browsers show `xn--` labels as Unicode, a lookalike vector, and RFC 5891 reserves `??--` labels. An all-digit slug reads like an id or a phone number. Rejected: banning `--` only at positions 3 and 4 (more rule for no gain); allowing all-digit slugs.
2. **Unicode is rejected, never folded.** After trimming, any character outside ASCII letters, digits and `-` is a format error. Only then is the input lowercased, which is an ASCII-only operation. Why: Unicode case mapping turns lookalikes into real letters (Kelvin sign to `k`; a Turkish locale maps `I` to `ı`). Rejected: NFKC folding (it accepts lookalikes silently); internationalized names (spoofing, and the pilot doesn't need them).
3. **One reserved list, `RESERVED_SLUGS` in `#modules/tenancy/slugs`, plus the brand.** Matched exactly after normalization. Any slug containing `tattoodrip` (hyphens ignored) is also refused. Four groups: hostnames and infrastructure (`www`, `api`, `app`, `admin`, `mail`, `cdn`, `static`, `status`, `staging`…); platform pages (`login`, `signup`, `onboarding`, `dashboard`, `settings`, `inbox`, `booking`…); trust and phishing words (`help`, `support`, `security`, `billing`, `payments`, `checkout`, `official`, `noreply`…); template accidents (`undefined`, `null`, `true`, `false`, `none`, so a `/t/${undefined}` bug never opens a real studio). `checkSlug(input)` is the one entry point: onboarding and settings use it now, TAT-32 later. A unit test fails if an entry is not otherwise a valid slug. Rejected: a database table (no admin UI, and a code change is reviewed); reserving third-party brands such as eSewa or Khalti (support handles disputes).
4. **New slugs only.** The rules apply when a slug is chosen (onboarding, settings). Existing slugs are kept as they are and copied into the registry unchanged, and they keep resolving everywhere, so a lookup pre-filters with `STORED_SLUG`, never `checkSlug` (see "For TAT-32"). Rejected: renaming offenders in a data migration, which would break the links this ticket protects.
5. **One registry of every slug a tenant has held: `tenant_slugs`.** Columns `id`, `tenant_id`, `slug` (`tenant_slugs_slug_unique`, platform-wide), `created_at`. The current slug is in it too. A slug in the registry is never given to another tenant. The unique index enforces that across tenants without any cross-tenant read, as `tenants_slug_unique` does today. Rejected: a table of old slugs only (two indexes: "rename away from X" and "create X" pass both at once); a SECURITY DEFINER "is it taken" check (check-then-insert races, and it gives an anonymous oracle).
6. **The database writes the registry.** An `AFTER INSERT OR UPDATE OF slug` trigger on `tenants` (`tenants_register_slug`: plpgsql, invoker rights, pinned `search_path`) inserts the new slug unless the tenant already holds it. So no code path (service, raw SQL, seeder, a future API) can change a slug without reserving it. Taking another tenant's old slug fails on `tenant_slugs_slug_unique`, which `createTenant` and `changeSlug` turn into `SlugTakenError`. Rejected: service code writing both tables (nothing stops a future writer from forgetting).
7. **Rows are permanent for the app.** Row-level security: SELECT for the current tenant or tenants where the user has a live membership (as `tenants_select`); INSERT with check tenant = current. There is no UPDATE or DELETE policy, so the app role changes nothing (0 rows). A CHECK (`tenant_slugs_slug_format`) holds the old shape, so stored slugs are always lowercase ASCII and the copied ones fit. The `NO ACTION` key to `tenants` blocks a hard delete of a tenant while it holds slugs. Releasing a slug is a deliberate operations act: the owner role deletes the row. There is no UI for it. Rejected: an append-only trigger (it would also block the owner's deliberate release); revoking privileges (the database README makes RLS and triggers the mechanism, not grants).
8. **Owners change the slug in Settings, at most 5 slugs per tenant.** A "Web address" section on the studio profile page posts to `PUT /t/:tenant/settings/slug`, which calls `TenancyService.changeSlug`. Switching back to one of the tenant's own old slugs is allowed and reserves nothing new, as long as it still passes the slug rules: the form checks it like any other choice. A kept slug that fails them (ruling 4: `a--b`, `12345`, `www`) keeps redirecting but cannot be chosen again once the tenant has left it. Why: without a rename, aliases have nothing that creates them. The limit counts the current slug, and it bounds squatting: every rename reserves a name forever. Rejected: a service with no UI (the ticket's redirect could not be used, and the code would sit dead until another ticket); unlimited renames; freeing the oldest slug at the limit (that breaks "never someone else's"); letting a tenant choose a kept slug that fails the rules again (a reserved name would come back through Settings, and the form would need a registry read).
9. **Dashboard: GET and HEAD on an old slug get a 302 to the same path and query under the current slug, for members only.** The middleware first tries the current slug (unchanged). On a miss it calls `currentSlugFor(user, slug)`, which RLS limits to the user's own tenants. Non-members, deleted tenants and unknown slugs get the same 404 as today, so the redirect reveals nothing. 302, not 301 or 308: a studio can switch back to an old slug, and a browser that cached a permanent redirect would then loop. Writes (POST, PUT, DELETE) on an old slug are a 404: forms come from pages rendered under the current slug, so a write never goes through an alias. Rejected: 307 or 308, which replay writes; serving the page under the old slug (two URLs per page).
10. **Lookups match exactly.** Only the validator normalizes. `/t/Black-Needle` stays a 404, and a path parameter is never case-folded (Unicode mapping on untrusted input). TAT-12 lowercases the hostname by DNS rules on its side.
11. **No cross-tenant function in TAT-24.** Uniqueness is an index, and the dashboard lookup is member-scoped. The unauthenticated lookup belongs to TAT-32 (contract below). Rejected: a `tenant_for_slug()` function with no caller yet.
12. **Artist slugs are unchanged.** They are path segments inside one studio, not hostnames. Reserved words for artist paths wait for the studio-page route (TAT-48), as TAT-31 ruled. The tenant rule must stay a subset of `ARTIST_SLUG`, because an independent artist's profile starts with the tenant slug. A rename doesn't touch that profile. Rejected: applying the tenant rules to artists (it breaks `a--b` artist slugs that TAT-31 allowed, with no hostname reason).
13. **No new rate limit.** Onboarding allows one tenant per account and sits behind signup's limit (TAT-8). A rename is owner-only, really happens and is capped by ruling 8, so probing with it uses up the studio's slugs. Whether a slug is taken is not secret: it is a public subdomain.

## Data and code

- **Migration** `1791630000000_create_tenant_slugs_table.ts` creates the table, the unique index on `slug`, the `tenant_id` index, `UNIQUE (tenant_id, id)` (catalog guard), the format CHECK, the copy `insert … select id, slug, created_at from tenants`, the trigger function and trigger, and RLS with `tenant_slugs_select` and `tenant_slugs_insert`. `down()` drops the trigger, the function and the table. `pnpm migrate` regenerates `database/schema.ts`.
- **`#modules/tenancy/slugs`** (pure): `RESERVED_SLUGS`, `MAX_TENANT_SLUGS = 5`, `STORED_SLUG` (the registry CHECK's shape, for lookups), `checkSlug(input)` returns `{ ok: true, slug }` or `{ ok: false, problem: "format" | "reserved" }`, and `withTenantSlug(url, slug)` rewrites `/t/<old>…` to `/t/<slug>…`.
- **Validators:** a `tenantSlug()` Vine rule built on `checkSlug`. It stores the normalized slug and reports "Use 3 to 63 lowercase letters, numbers and single hyphens, with at least one letter. Don't start or end with a hyphen." or "This address is reserved. Try another one." It is used by `createTenantValidator` and a new `changeSlugValidator`.
- **Model** `TenantSlug` (read-only, from `TenantSlugSchema`); `Tenant.slugs` (hasMany).
- **`TenancyService`:** `createTenant` also maps `tenant_slugs_slug_unique`. `changeSlug(tenant, slug)` works in a savepoint. It locks the tenant row, and the stored slug (not the caller's copy) decides whether this is a no-op. It refuses a new slug when the tenant already holds `MAX_TENANT_SLUGS` (`SlugLimitError`), saves the slug (the trigger registers it), and maps both unique violations to `SlugTakenError`. It returns the locked tenant. `currentSlugFor(user, slug)`: the current slug of the user's live tenant that once held `slug`, else null.
- **Middleware:** on a miss, for GET or HEAD, `currentSlugFor` then `redirect().toPath(withTenantSlug(request.url(true), current))`. The 404 is unchanged otherwise.
- **Settings:** `StudioSlugController.update`. `SlugTakenError` becomes the field error "This address is already taken. Try another one." `SlugLimitError` becomes "Your studio has used 5 addresses, the most allowed. You can still switch back to an earlier one." Success flashes "Address changed. Links to the old address still work." and redirects to `tenant.settings.profile` under the new slug. Onboarding's slug hint changes to "Lowercase letters, numbers and single hyphens, 3 to 63 characters."

## For TAT-32 (contract, posted as a carry-forward)

- Pre-filter a path `:slug` with `STORED_SLUG` from `#modules/tenancy/slugs` (the shape the registry's CHECK enforces): a slug that does not match is a 404 without a query. Do not use `checkSlug` for this. It is for slugs someone chooses (onboarding, rename) and refuses legacy slugs that ruling 4 keeps (`12345`, `a--b`, a now-reserved word like `www`), which would make those studios unreachable here while their dashboard works. Then match the slug exactly against `tenant_slugs` joined to a live tenant. The public request has no user, so this needs a SECURITY DEFINER function. The README's "no arguments" rule must be amended for one text argument compared with `=`. The function returns at most `(tenant_id, current_slug)` and never lists tenants. Add it to `DEFINER_FUNCTIONS` with its own spec.
- An old slug serves the same tenant (the OpenAPI already says "Old slugs resolve as aliases"). Storefront pages (TAT-48, TAT-12) redirect to the current slug with 302 (ruling 9). Import `STORED_SLUG` (and `checkSlug`, `RESERVED_SLUGS` if a path ever lets a slug be chosen); never copy them.

## Tests

- **Unit** (`slugs.spec.ts`, table-driven): valid slugs; too short and too long; edge hyphens; `--` and `xn--`; all digits; spaces, `_`, `.`, `/`; Unicode (Kelvin sign, fullwidth, Cyrillic `а`, `ä`, zero-width space, `İ`) refused, never folded; reserved names in any case and padded; the brand inside a slug; every `RESERVED_SLUGS` entry otherwise valid; `STORED_SLUG` accepts legacy slugs (`12345`, `a--b`, `www`) and refuses what the CHECK refuses; `withTenantSlug`. Validator tests for both validators (normalized value, both messages).
- **Database** (`slug_registry.spec.ts`): creating registers the slug; a raw slug update registers the new one and keeps the old; another tenant's old slug is refused on update and on create; a tenant can return to its own old slug; RLS (rows hidden from other tenants and non-members, visible to members; insert for another tenant refused; update and delete affect 0 rows); the format CHECK, and that `STORED_SLUG` is its shape; catalog guard `EXPECTED_POLICIES` gains `tenant_slugs`.
- **Service** (`change_slug.spec.ts`): rename keeps the old slug; same slug is a no-op; another tenant's current or old slug is `SlugTakenError` with nothing changed and the transaction still usable; switching back adds no row; a chain A to B to C keeps all three, and A and B resolve to C; the limit, with switching back still allowed at the limit; `currentSlugFor` for member, current slug, unknown, non-member, removed member and deleted tenant; from tenant B's context, tenant A's old slug resolves to nothing.
- **HTTP:** old-slug redirects (path and query kept, the bare `/t/<old>`, the first link of a chain going straight to the current slug, HEAD); a write on an old slug is a 404 with nothing changed; another studio's old slug, a deleted studio's and a mixed-case one are 404s. Settings rename (success and flash, normalization, reserved, format, taken current, taken old, the limit, same slug, a kept slug that fails the rules still redirects but can't be switched back to, artist 404). Onboarding refuses reserved, `--`, all-digit, Kelvin-sign and another studio's old slug.
- **Isolation:** a `PUT /t/:tenant/settings/slug` case in `cases.ts`, whose snapshot is the tenant row plus its slugs.
