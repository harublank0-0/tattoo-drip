# Wire the SDK: per-request client, TattooProvider, SSR prefetch (TAT-23)

Date: 2026-10-18
Refs: TAT-23. Builds on TAT-12 (`tenantMiddleware`, `requestStudio()`, `parseStorefrontConfig` with `API_URL` and `STOREFRONT_URL`, `lookUpTenant`, the storefront's `node:test` runner) and the built SDK chain (TAT-32/51/65: `createTattooClient` with `key`, `timeoutMs`, `fetch`; `TattooApiError` with `status`, `code`, `retryAfter`; `tattooQueries`, `tattooKeys`, `TattooProvider`). Blocks TAT-48. Written without the user (unattended run): every open question is a ruling below.

## Goal

Every storefront render gets its own `QueryClient` and SDK client: on the server one per request (the studio TAT-12 confirmed, plus the server key), in the browser one per tab (no key). Loaders prefetch with `tattooQueries.*`, the cache is dehydrated into the page and hydrated without a second fetch, and `TattooProvider` makes the `@tattoo-drip/react` hooks work in any component. Proven end to end by the one read that exists: the root loader loads `studio.get` and the page `<title>` becomes the studio's name. The mock page bodies stay until TAT-48.

## Rulings

1. **Scope: wiring, proven by one real read.** The root route's loader loads the studio and its `head` uses `studio.name` for `<title>` ("Tattoo Drip" if absent); no route file, so no `generate-routes`. Rejected: a demo route (a route file and a regenerated route tree for throwaway code); waiting for TAT-44's endpoints.
2. **One router, one `QueryClient`, one SDK client.** All three are made in `getRouter()`, which Start calls once per server request (`createStartHandler`'s per-request `routerPromise`) and once per tab (`hydrateStart`). Nothing is created at module scope; `src/integrations/tanstack-query/root-provider.tsx` goes. Start's cleanup clears the per-request `QueryClient` after the response (the SSR query integration's `teardown`). Rejected: module singletons (one cache for every studio on a server); a client per loader call.
3. **Router context `{ queryClient, tattoo }`; `tattoo` is a `TattooClientRef`.** A set-once holder: connected inside `getRouter()` on the server and in the router's `hydrate` in the browser, which runs before the first route matches. Loaders read `context.tattoo.client`. The client never goes into a `beforeLoad` return value or loader data: the router serializes both into the page (`dehydrateMatch`: `b`, `l`). Rejected: the client itself in context (the browser can't make one before hydration); building it from `location.hostname`.
4. **Server client.** `createTattooClient({ baseUrl: API_URL, tenant: studio.slug, key: STOREFRONT_SERVER_KEY, timeoutMs: 5_000 })`, where `studio` is `requestStudio()`, the current slug TAT-12's lookup confirmed. The middleware's `Studio` is seeded into the cache (`setQueryData(tattooKeys.studio(slug))`), so a render asks the API once per page (the lookup), not twice. No retries on the server; 5 s like the lookup. Rejected: a second `getStudio` per page; the SDK's 10 s default; reusing the lookup's client (built for a slug that may be old).
5. **The browser gets `{ apiUrl, tenant }` and nothing else**, through the router's `dehydrate`/`hydrate` (the SSR query integration chains them), checked on arrival (an http(s) origin, a stored-shape slug, else a fixed error). The tenant is the slug the server confirmed from `Host`; the browser never parses its host (TAT-12 ruling 4) and so can't disagree with the HTML it was sent. Rejected: a `VITE_API_URL` (inlined at build: a second value to keep equal, a rebuild to change, previews bake one); a meta tag (a second channel for what the router already carries).
6. **One `API_URL` for server and browser.** It is sent to every visitor, so it must be the API's public origin; TAT-12 already refuses http outside loopback, so an internal `http://platform:3333` can't be set by mistake. Rejected: a `PUBLIC_API_URL` now (the planned Vercel deployment reaches the API over the internet). If a private path is ever needed, add a server-only `API_INTERNAL_URL` and keep `API_URL` public.
7. **`STOREFRONT_SERVER_KEY`: optional now, plumbed through both server calls.** Read by TAT-12's `parseStorefrontConfig` (so `pnpm dev` checks it at start): when set it must be 32 to 256 token68 characters (`openssl rand -base64 32`), and the error names the variable and the rule, never the value. `serverKey` is on the config object only when set. Both server-side calls send it as `Authorization: Bearer` (the SDK's `key`): TAT-12's lookup and the per-request client. The platform ignores the header until TAT-38. Rejected: required now (a value that does nothing); deferring it to TAT-38 (both call sites would change again, and the ticket asks for the plumbing).
8. **The key never leaves the server process.** Only `src/tenancy/config.ts` reads it, from `process.env` (never `VITE_`, never `src/env.ts`, never Vite `define`); `TattooClientRef` and the SDK client hold it in closures and private fields. Only successful and still-pending queries are dehydrated (`shouldDehydrateQuery`), a pending query's rejection is redacted, failed reads stay on the server, and the router serializes errors as their message only (`ShallowErrorPlugin`). Three checks: a unit test of everything the page carries, a grep of the client bundle, and a production-server run with a canary key and a fake API. Rejected: relying on review.
9. **Query defaults.** `staleTime` 60 s, the API's own `max-age` (TAT-32), so hydrated data isn't fetched again on mount. Browser retries: timeouts, network errors and 5xx twice (1 s, then 2 s); a 429 once, after its `Retry-After` when that is at most 10 s; never a 4xx (404, 409, 422) and never a `Retry-After` over 10 s. The server never retries (a page shouldn't wait seconds; TAT-12's 503 page covers an API that is down). Mutations keep their own `retry: false`. Rejected: TanStack's defaults (`staleTime` 0 refetches every hydrated query from every visitor; 3 retries of every error, `Retry-After` ignored); `staleTime: Infinity` (an open tab never sees an owner's edit).
10. **The deposit query is always stale.** `tattooQueries.deposit` gets `staleTime: 0`, so TAT-65's "refetched when the window regains focus" holds under the 60 s default (as `retry: false` on mutations holds "whatever the app's QueryClient defaults say"). Rejected: storefront `setQueryDefaults` (its key prefix can't skip the tenant).
11. **Loaders use `queryClient.query({ ...tattooQueries.x(client), staleTime: "static" })`.** The installed TanStack Query (5.104) deprecates `ensureQueryData` for exactly this call, which behaves the same (cached data, else one fetch) and keeps no state on the query. `rethrowAsNotFound(error)` turns the API's 404 `not_found` (a studio or record that went away) into the router's `notFound()`; any other error reaches the route's error component. The router's default components stay until TAT-48. Rejected: `ensureQueryData` (deprecated, removed in v6).
12. **`TattooProvider` in the root shell**, from `Route.useRouteContext()`, inside the `QueryClientProvider` that `setupRouterSsrQueryIntegration` wraps around the whole router. Rejected: the router's `Wrap` option (outside the router context, so a component made per router); a second `QueryClientProvider`.
13. **Cancellation needs no new wiring.** The query options already pass Query's `signal` to the SDK; when a visitor disconnects, Start's cleanup clears the request's `QueryClient`, which cancels its reads. The router's loader signal is not forwarded: a navigation away still fills the cache. Rejected: wiring `request.signal` into the client.
14. **Packages from source.** `@tattoo-drip/react` joins the storefront as `workspace:*` (TAT-12 added the SDK), consumed from `src/` as the packages' own guide says: Vite and `tsx` transform it, with no build step and no `ssr.noExternal` or `optimizeDeps` setting (Vite never externalizes linked packages). A test fails if `packages/react` and the storefront resolve different copies of React or TanStack Query (the hooks would see no `QueryClient`). The storefront's typecheck covers the packages' source. Rejected: consuming `dist/` (a build before every dev run); Vite `resolve.dedupe` (hides a split lockfile instead of failing).
15. **Tests: `node:test` + `tsx` in `apps/storefront/test/api/`**, TAT-12's runner. The glue (`src/api/request.ts`, `router.tsx`, `__root.tsx`) is covered by typecheck, build, the bundle grep and the production-server run. Rejected: booting Start in tests (no harness).

## For later tickets

- **TAT-38 (platform):** a `STOREFRONT_SERVER_KEY` setting with the same value; parse `Authorization: Bearer` in the public API's rate-limit middleware only; compare in constant time (`timingSafeEqual` over SHA-256 digests); a match gets the storefront's own budget instead of the per-IP limit, the per-tenant limit still applies; no header or a wrong key is anonymous (or a 401: TAT-38 decides), never logged or echoed. Keep CORS refusing `Authorization`, add no per-caller headers to cacheable responses (TAT-32 rulings 10, 11, 16), and make the key required in production in both apps (`parseStorefrontConfig` when `NODE_ENV=production`). Decide whether keyed calls forward the visitor's address (the SDK's `fetch` option can add a header).
- **TAT-48:** loaders as in ruling 11 (`tattooQueries.artists`, `artist` with `rethrowAsNotFound`), its own not-found and error components, page `Cache-Control`, per-page titles, TAT-12's canonical link. `useSuspenseQuery` in components streams (pending queries dehydrate).
- **TAT-57:** `useCreateInquiry()` uses the browser client as is. A future CSP must allow `API_URL` in `connect-src`.
- **TAT-65b:** browser-only `useDeposit`/`useSubmitDepositProof` work as is; ruling 10 keeps the focus refetch.
- **TAT-13 (user):** set `STOREFRONT_SERVER_KEY` in Vercel and on the platform once TAT-38 checks it.
- A studio renamed while a tab is open keeps the old slug in that tab until a reload, which TAT-12 redirects.
